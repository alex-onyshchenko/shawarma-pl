# ШаурМіша

Независимые приложения для клиента, кухни и администратора с общим HTTP/SSE API.
MVP работает с **одной активной демо-точкой**. Можно создавать и редактировать
дополнительные точки, но они остаются неактивными и не принимают заказы.

| Подпроект | Каталог | Порт |
| --- | --- | --- |
| Telegram Mini App | `apps/client` | 3000 |
| Терминал кухни | `apps/kitchen` | 3001 |
| Sync API + SQLite | `services/sync` | 3002 |
| Telegram Bot webhook | `services/telegram-bot` | 3005 |
| Аналитика, опционально | `apps/analytics` | 3003 |
| Админ-панель | `apps/admin` | 3004 |

Каждый подпроект имеет собственные package.json, lock-файл и Dockerfile.
Импортов между подпроектами нет. Корневой package.json содержит удобные
команды запуска; npm workspaces и общие runtime-пакеты не используются.

## Docker

```bash
npm run env:setup  # создаёт env-файлы из шаблонов, не перезаписывает существующие
docker compose up --build -d
# С аналитикой:
docker compose --profile analytics up --build -d
```

Откройте `http://localhost:3004/admin/`. Вход — браузерный Basic Auth, временно admin / admin. Настройки `ADMIN_BASIC_USER` и `ADMIN_BASIC_PASSWORD` находятся в приватном env Sync. На Linode админка размещается на `/admin/`, Caddy защищает и страницу, и `/api/admin/*`; Sync повторно проверяет Basic Auth. Ключи не попадают во frontend-сборку. Старый сессионный API ADMIN_TOKEN сохранён для совместимости, если Basic Auth не настроен. Кнопки кухни работают без пароля.

Каждый frontend image собирается из своего каталога и раздаёт статику через
nginx. `/api` проксируется к `sync:3002`, SSE передаётся без буферизации.
Для размещения frontend-контейнера вне Compose подмонтируйте nginx-конфиг
с доступным адресом Sync. Админ-панели требуется same-origin API proxy.

## Что можно менять в админ-панели

- Текущую точку: название, адрес, описание, телефон и часовой пояс.
- Дни и часы работы, выходные и исключения на конкретные даты.
- Шаурму и напитки: размеры, вес, цены, видимость, наличие и загружаемые фото.
- Общие ингредиенты: названия и необязательные фото; без фото показывается иконка. Состав блюда формируется из выбранных ингредиентов.

Каталог общий; цены, наличие и видимость задаются отдельно для каждой точки. Создание новых неактивных точек остаётся в API, существующие точки доступны в селекторе. Админка работает с SQLite только через Sync. Загруженные фото хранятся в постоянном каталоге media, пути — в БД. Подробности: [apps/admin/README.md](apps/admin/README.md).

Клиент получает активную точку и её меню через API и периодически обновляет их. Перед оформлением сервер проверяет наличие,
рассчитывает цены и скидки из каталога и сравнивает ожидаемую сумму. Если
меню изменилось, корзина обновляется, и клиент подтверждает новую сумму.
Оформленные заказы сохраняют снимок названий, состава и цен.

## Текущий клиентский MVP

- Логотип «ШаурМіша» расположен в шапке. Под адресом — ручной статус кафе
  «Відчинено» / «Зачинено» вместо баннера. Повар переключает его
  иконками открытого замка (открыть) и закрытого замка (закрыть) в терминале без пароля (подпись показывается при наведении).
  Иконка чашки «Обідня перерва» приостанавливает новые заказы и показывает клиенту
  отдельный статус; «Завершити перерву» возвращает приём заказов. Статус хранится в SQLite, передаётся клиенту через SSE и
  polling; закрытие блокирует новые заказы, не затрагивая текущие.
  Расписание определяет доступные слоты, но не переключает ручной статус.
- На главной только «Шаурма» и «Напої», без баннера и поиска.
- Фирменная (отмечена «🔥 Найпопулярніша»): 350/450/550 г за 200/230/260 ₴.
- Классическая: 350/450/550 г за 190/220/250 ₴.
- Говяжья: только 450 г за 230 ₴.
- Фотографии классической, фирменной и говяжьей шаурмы показаны крупно
  слева в вертикальном списке, в выборе размера и корзине.
- Фото позиций имеют одинаковый портретный формат 2:3 в меню, выборе
  размера и корзине.
- В карточке шаурмы — размер, количество и поджарка лаваша «Слабіше» /
  «Звичайна» / «Сильніше», без свободного комментария. Стандарт — обычная поджарка. Вариант виден повару и не меняет цену.
- Для «Якнайшвидше» время выдачи — текущее +15 минут с округлением вверх
  до четверти часа: 16:53 → 17:15. В кошике показан ближайший срок.
- На подтверждении заказа вместо этапов показан состав заказа списком
  над суммой: количество, размер и поджарка лаваша для каждой позиции.
- В кухне нет ссылки на меню клиента и счётчика над иконкой архива.
  Дополнения (салфетки) оформлены отдельной секцией с пиктограммой.
- В терминале кухни вместо тестового заказа — ручное создание: шаурма,
  размер, количество и время готовности. Время подтверждается при создании
  одним запросом; повтор запроса не создаёт дубликат. Ручной заказ доступен
  даже вне расписания, в закрытом кафе и на обеденном перерыве. Время
  готовности — в ближайшие 24 часа, шаг 15 минут, минимум через 15 минут.
- Только самовывоз: м. Полтава, вул. Соборності, 46. Адрес редактируется в
  админке и передаётся в клиент через API. Доставка и онлайн-карта неактивны.
- Скидка за самовывоз отключена. В корзине нет промокода и общего комментария;
  телефон необязателен, можно добавить только салфетки. Оплата при получении.
- Размеры и их цены редактируются для выбранной точки в админке.

При первом запуске новой версии существующая БД получает одноразовую
миграцию меню и настроек демо-точки. Старые шаурмы скрываются, история заказов
сохраняется. Следующие перезапуски не перезаписывают изменения администратора.

## Хранение

Используется встроенный `node:sqlite` в Node.js 24. Дополнительный сервер БД
не нужен. Таблицы хранят точки, каталог, меню, расписание, журнал и сессии;
состояние заказов сохраняется отдельным снимком в SQLite.

В Docker база находится в `/app/data/shawarma.sqlite`, каталог подключён
к постоянному тому `sync-data`. Обычный перезапуск контейнера сохраняет
настройки и заказы. Удаление тома удаляет базу. При локальном запуске файл
создаётся в `services/sync/data/`; путь можно задать через `DATABASE_PATH`.
SQLite, приватные env-файлы и node_modules исключены из Git. В Docker build context фронтенда включены только `.env.dev` и `.env.prod` с публичными настройками; env-файлы Sync в образ не копируются.

Демо-точка и меню создаются только при первом запуске пустой базы.
Заказы и архив изначально пустые; демонстрационная история не генерируется.
`POST /api/reset` очищает текущие и архивные заказы с сохранением последовательности номеров. Часовой пояс и график берутся из БД точки; изменения выполняются в панели администратора.
Начальные часы — 10:00–22:00, часовой пояс — Europe/Kyiv.

## Локальная разработка

Потребуется Node.js 24 и npm.

```bash
npm run setup
```

В отдельных терминалах:

```bash
npm run server
npm run dev:client
npm run dev:kitchen
npm run dev:admin
# Опционально:
npm run dev:analytics
```

Для локальной админки задайте `ADMIN_BASIC_USER=admin` и `ADMIN_BASIC_PASSWORD=admin` в `services/sync/.env.dev`.
`npm run server` использует dev; `npm run server:prod` — prod. Корневой `.env` больше не передаёт ключ администратора в Sync.
Команды `npm run dev` и `npm run dev:kds` сохранены как алиасы.

Любое frontend-приложение можно скопировать в отдельный репозиторий:

```bash
cd apps/admin
npm ci
npm run dev
npm run build
npm run preview
```

`SYNC_API_TARGET` в `.env.dev` / `.env.prod` фронтенда задаёт адрес Vite dev/preview
proxy, по умолчанию `http://127.0.0.1:3002`. Client, Kitchen и Analytics
также поддерживают `VITE_SYNC_API_URL` для публичного адреса API. Значения
`VITE_*` встраиваются при сборке. Для Admin используйте same-origin proxy,
сохраняющий заголовок Host вместе с портом, как в предоставленных конфигах.

## Время выдачи

- По умолчанию — «Якнайшвидше», минимум 15 минут приготовления.
- Точный час — только сегодня, кратный 15 минутам, в рамках расписания точки.
  Открытие выбора в 14:22 даёт первый слот 14:45.
- Перед имитацией оплаты устаревший слот автоматически переносится вперёд.
- Кухня один раз подтверждает базовый час или добавляет 5/10/15 минут.
- Принятие оставляет заказ в очереди. Приготовление запускается отдельной кнопкой.
- Ранний старт/готовность более чем за 20 минут до подтверждённой выдачи
  требует явного подтверждения. Таймер показывает оставшееся время.
- Для доставки указан момент готовности к передаче курьеру, без времени в пути.
- Стоп точки блокирует новые оформления, но не выполнение существующих заказов.

Оплата — наличными при получении. При настроенном `TELEGRAM_BOT_TOKEN` Sync отправляет реальные Telegram-уведомления: заказ оформлен, время подтверждено, готовится, готов к выдаче. Клиент запрашивает разрешение на сообщения и после оформления предлагает «Відстежувати статус» в чате бота. Клиент не получает общую ленту заказов кухни.
Полная авторизация клиентов и кухни, реальные платежи и много активных точек
остаются за рамками этого MVP.

## Проверки

```bash
npm run build
npm run check
npm test
npm run test:integration
```

Тесты запускают изолированные серверы и базы, не меняя рабочую демо-точку.
Проверяются слоты и граничные времена, переходы кухни, повторные запросы,
административные сессии, запрет активации черновиков, цены и наличие,
расписание, сохранение SQLite и взаимодействие независимых прокси.
Контракт API описан в `services/sync/API.md`.

### Деплой клієнта на Vercel і запуск у Telegram

Клієнт має мобільний інтерфейс без симулятора. Root Directory у Vercel — `apps/client`. Поточний Vercel build — `npm run build`, із підключенням до Sync через `VITE_SYNC_API_URL=https://139-162-130-216.ip.linodeusercontent.com`. Автономний перегляд без замовлень доступний окремо через `npm run build:menu`; Sync із SQLite розгортається окремо. Покрокова підготовка, налаштування BotFather та межі поточного MVP: [apps/client/DEPLOYMENT.md](apps/client/DEPLOYMENT.md).

### Окружения dev / prod

У каждого из шести сервисов есть `.env.dev` и `.env.prod`. Реальные файлы не коммитятся; в Git хранятся соответствующие `.env.dev.example` и `.env.prod.example`. `npm run env:setup` создаёт отсутствующие файлы, не меняя существующие. Административные пароли и `TELEGRAM_BOT_TOKEN` задаются только в приватном env Sync и не попадают во frontend.

| Действие | Команда | Настройки |
| --- | --- | --- |
| Frontend: разработка | `npm run dev` | `.env.dev` |
| Frontend: обычная сборка | `npm run build` | `.env.prod` |
| Client: Vercel menu preview | `npm run build:menu` | dev, без API и заказов |
| Frontend: явный выбор сборки | `npm run build:dev` / `npm run build:prod` | выбранное окружение |
| Frontend: preview | `npm run preview` / `npm run preview:dev` | prod / dev; сначала собрать тем же mode |
| Sync: разработка | `npm run dev` / `npm run start:dev` | `.env.dev` |
| Sync: production | `npm start` / `npm run start:prod` | `.env.prod` |
| Docker: dev | `APP_ENV=dev docker compose up --build -d` | dev-файлы всех сервисов |
| Docker: prod | `APP_ENV=prod docker compose up --build -d` | prod-файлы всех сервисов |

Команды frontend/Sync из таблицы выполняются в каталоге соответствующего сервиса. Compose передаёт Sync выбранный env-файл во время запуска, а фронтендам — mode при сборке. После изменения frontend env нужна пересборка. `VITE_*` публичны; пароли и токены в frontend env не хранить. Старые универсальные `.env` внутри сервисов больше не используются; Vite имеет стандартную поддержку `.env.local`, но проекту достаточно пары dev/prod.

Dev и prod по умолчанию используют разные SQLite-файлы в одном Docker-томе; переключение на prod не переносит туда dev-данные автоматически. Опубликованному клиенту нужна фактическая HTTPS-адреса API, описанная в инструкции деплоя.

Справка: [Vite modes](https://vite.dev/guide/env-and-mode), [Docker env_file](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/).


### Окремий Telegram-бот

`services/telegram-bot` обробляє `/start` і `/help` та повертає кнопку відкриття клієнта. Це незалежний Node.js/Vercel-проєкт без Sync і бази даних. Локальний запуск — `npm run dev:bot`, тести — `npm run test:bot`; Docker-профіль — `bot`. Він не активується у стандартному Compose-запуску. Окремі `.env.dev` / `.env.prod` виключені з Git.

Підпроєкт підготовлений до деплою; реальний Telegram webhook потрібно зареєструвати після створення окремого Vercel-проєкту та заповнення приватних налаштувань. Інструкція: [services/telegram-bot/README.md](services/telegram-bot/README.md).

### Клієнтські обмеження

Перед реальним меню клієнт один раз ділиться номером Telegram. Номер
для дзвінків у кошику можна змінити. Сервер вимагає перевірений контакт,
обмежує одну позицію 5 одиницями (усі варіанти разом), кошик — 10
товарами, готівку — 500 грн включно. Більші замовлення й клієнти після
неявки тимчасово не можуть оформлювати замовлення до підключення
онлайн-передоплати. Прапорець після неявки не має строку дії.
Меню переглядати можна. На production повторно зареєструйте webhook
бота для перевірки контактів; бот потребує `SYNC_API_URL`.
Кухонний API за рішенням власника відкритий, тому клієнтські правила
можна обійти ручним маршрутом; це свідоме обмеження MVP.
