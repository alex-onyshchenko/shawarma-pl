# ШаурМіша — проста адмін-панель

React/Vite, порт 3004. На Linode доступна за `/admin/` на тому самому домені, що й Sync. Адмінка звертається лише до Sync API й не відкриває SQLite напряму.

Три розділи:
- Заклад: назва, адреса, телефон, часовий пояс, тижневий графік та особливі дні.
- Шаурма: розміри, ціни, вага, фото, видимість і наявність.
- Напої: ціни, об’єм, фото, видимість і наявність.

Інгредієнти додаються й редагуються всередині позиції: блоки з іконкою листочка, назвою та необов’язковим фото. Можна обрати наявний або створити новий інгредієнт. Назви й фото спільні між рецептами; без фото — іконка. Окремого розділу інгредієнтів немає.

Створення додаткових точок залишається доступним через API; вони неактивні. Існуючі точки можна обрати у верхній частині сторінки. На основному екрані немає аналітики, замовлень чи модифікаторів.

## Вхід

Браузерний Basic Auth, тимчасово `admin` / `admin`. Caddy захищає `/admin/` та `/api/admin/*`, Sync додатково перевіряє той самий Basic Auth. Пароль задається в приватному env Sync через `ADMIN_BASIC_USER` і `ADMIN_BASIC_PASSWORD`. Скрипт SSH-деплою генерує `ADMIN_BASIC_HASH` для Caddy; секрети не входять до frontend-збірки. Окремої форми входу в React немає. Старий сесійний API збережено для сумісності там, де Basic Auth не налаштований.

## Розробка

```bash
npm ci
npm run dev
npm run build
npm run preview
```

`SYNC_API_TARGET` у `.env.dev` / `.env.prod` задає проксі API та фотографій. Для локальної адмінки налаштуйте Basic Auth у приватному env Sync. Production Vite base — `/admin/`; nginx підтримує цей префікс. Деплой на Linode: `./deploy/deploy-sync.sh` з кореня репозиторію.

Фото завантажуються через автентифікований `POST /api/admin/images`: JPEG/PNG/WebP до 5 МБ і 40 МП. Sync перевіряє, зменшує до 1600 px і зберігає WebP в `data/media/` на постійному volume. У SQLite зберігається лише шлях. Окремо копіюйте і SQLite, і каталог `media/` під час backup. Старі фото автоматично не видаляються, тому незбережене завантаження не може зламати фото чинних позицій.
