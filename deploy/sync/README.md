# Sync через SSH: Docker + SQLite + Caddy HTTPS

Деплой запускає лише Sync та Caddy. Усі маршрути Sync доступні через HTTPS без додаткових обмежень Caddy. Наявна авторизація `/api/admin/*` зберігається; кухонні операції, список замовлень та SSE наразі не вимагають входу.

## Запуск зі свого комп’ютера

На сервері потрібні Docker з Compose v2+, Python 3, curl та доступ до Docker без інтерактивного sudo. Для першої установки використовується root. У Linode Cloud Firewall відкрийте TCP 80/443 та збережіть SSH. Якщо на сервері є інший firewall, також відкрийте ці порти вручну. Скрипт не змінює UFW або інші firewall.

З кореня репозиторію:

```bash
./deploy/deploy-sync.sh
```

За замовчуванням: `root@139.162.130.216`, API `139-162-130-216.ip.linodeusercontent.com`, каталог `/opt/shaurmisha-sync`.

Інший сервер або домен:

```bash
./deploy/deploy-sync.sh root@139.162.130.216 api.example.com
```

Домен має вказувати на сервер. Перша SSH-сесія попросить перевірити fingerprint ключа сервера; далі використовується звичайна SSH-авторизація ключем або паролем. Опціональні параметри: `SSH_PORT=2222 DEPLOY_DIR=/opt/shaurmisha-sync ./deploy/deploy-sync.sh user@server api.example.com`.

Скрипт передає поточні локальні JS-файли Sync, package/lock, Dockerfile та конфігурацію деплою, включно з незакоміченими змінами. Локальні `.env`, бази та `node_modules` не передаються. На сервері створюється `.env.prod` з випадковим `ADMIN_TOKEN` і правами 600. При повторному запуску ключ і решта налаштувань зберігаються; змінюється лише `API_HOST` на переданий hostname. Секрети не друкуються та не потрапляють у Git.

Caddy автоматично отримує та продовжує сертифікат. Скрипт перевіряє конфігурацію, стан контейнерів і HTTPS `/api/health` із перевіркою сертифіката. Порт Sync 3002 прив’язаний лише до loopback; зовнішні запити проходять через Caddy на 443.

## Перезапуск і збереження даних

Обидва сервіси мають `restart: unless-stopped`: Docker автоматично перезапускає контейнер при завершенні його процесу та після перезавантаження сервера. Після ручного `docker stop` або `docker compose stop` контейнер залишається зупиненим до явного запуску. Docker daemon має запускатися разом із системою.

Healthcheck Sync перевіряє `/api/health`. Статус `unhealthy` без завершення процесу сам по собі не запускає перезапуск; для зависань потрібен окремий watchdog.

SQLite зберігається у volume `shaurmisha-sync-data`, сертифікати — в окремих volumes. Оновлення та перезапуски не видаляють ці дані. Не використовуйте `down -v`, якщо потрібно їх зберегти. Постійний volume не замінює резервну копію.

## Оновлення та обслуговування

Для оновлення повторіть ту саму команду деплою. На сервері:

```bash
cd /opt/shaurmisha-sync/deploy/sync
docker compose --env-file .env.prod ps
docker compose --env-file .env.prod logs --tail 100 sync caddy
```

Приватні налаштування змінюйте в серверному `.env.prod`; для застосування повторіть деплой. Скрипт не змінює ключ адміністратора, наявну базу чи сертифікати.

Часовий пояс, тижневий графік та винятки беруться з бази точки й редагуються через Admin. При першому запуску порожньої бази створюється демо-точка з Europe/Kyiv та графіком 10:00–22:00. Ці значення не задаються через env і не перезаписують збережені налаштування.

Для уведомлений добавьте в приватный серверный `.env.prod` переменную `TELEGRAM_BOT_TOKEN` бота @shaurmisha_pl_bot и повторите деплой. Скрипт сохраняет существующий токен и не копирует локальные секреты.
